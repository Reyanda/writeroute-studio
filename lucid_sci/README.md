# LUCID-SCI
## Precision-Preserving Scientific Writing Toolkit

**Governing rule:** simplify the route to the idea, never the idea itself.

LUCID-SCI is a writing and editing system for producing scientific and technical prose that is rigorous enough for specialist scrutiny but clear enough for an intelligent reader outside the immediate field. Its target is the cross-disciplinary scholarly register commonly expected by broad-readership journals, technical commissions, funders, policymakers and multidisciplinary research teams.

It is not a lay-summary generator, a popular-science voice, or a device for removing all technical terminology. It preserves the scientific claim, design, estimand, population, comparison, outcome, uncertainty, assumptions and limits while reducing unnecessary lexical, syntactic and inferential difficulty.

## Toolkit contents

- `SKILL.md`: the complete operational writing skill.
- `RUBRIC.md`: a 100-point assessment and hard-failure gates.
- `PHRASEBOOK.md`: sentence patterns, terminology decisions and claim-calibration language.
- `EXAMPLES.md`: before-and-after examples for abstracts, methods, results and discussion.
- `PROMPTS.md`: reusable prompts for drafting, rewriting and auditing.
- `lint_rules.yaml`: machine-readable review triggers for a writing tool.
- `EVIDENCE_BASE.md`: the journal guidance and research used to build the toolkit.

## Default register

- Educated, cross-disciplinary scientific audience
- Formal but natural
- British English
- No slang, conversational fillers or inflated academic theatre
- No em dashes by default
- Active voice where it clarifies agency; passive voice where the object or process is the true topic
- Exact technical terms retained when they carry meaning that ordinary words cannot
- Every technical term explained on first use unless it is genuinely standard for the intended audience

## Five-minute use

1. Identify the intended reader and the decision or understanding the text should support.
2. Record the scientific invariants using the Semantic Checksum in `SKILL.md`.
3. Draft or rewrite using the LUCID sequence.
4. Run the hard-failure gates in `RUBRIC.md`.
5. Use the final fidelity check to confirm that clarity has not changed the science.

## Core output contract

Every LUCID-SCI edit should produce:

1. Revised text
2. Scientific fidelity ledger
3. Jargon decisions
4. Claim-calibration notes
5. Unresolved ambiguities or missing information
6. Quality score and priority revisions
